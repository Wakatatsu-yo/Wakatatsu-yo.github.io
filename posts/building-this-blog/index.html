这个博客如何搭建

Hugo、PaperMod 与 GitHub Pages：从本地 Markdown 到公开网页。

网站的组成#

这个博客使用 Hugo 将 Markdown 文章生成静态网页，PaperMod 提供页面主题，GitHub Pages 负责网站托管。

源码保存在私有仓库，另一个公开仓库只保存生成后的 HTML、CSS、JavaScript、图片及订阅文件。已经发布的文章可以在浏览器里阅读，网页文件也可以查看；未发布的 Markdown 草稿保留在私有源码中。

本地写作#

文章和配图放在同一个文件夹中。正式构建会排除草稿和未来日期文章；本地预览可以显示草稿，方便边写边检查。

分类用于区分技术与生活，标签用于连接不同文章。每篇文章使用固定的英文 slug，便于保留稳定的网址。

发布过程#

  1. 在本地编辑 Markdown。
  2. 启动预览，检查文字、图片和目录。
  3. 运行发布脚本，生成一份干净的正式网页。
  4. 将源码推送到私有仓库备份。
  5. 将生成后的网页推送到公开发布仓库。
  6. GitHub Pages 自动部署更新。

构建失败时，发布脚本会停止，线上继续保留上一次成功发布的内容。

Set-Location F:\Code\wakatatsu-yo-blog
.\scripts\Preview.ps1
# 检查后停止预览，运行发布
.\scripts\Publish.ps1 -Message "更新博客"

本次使用的 Hugo 版本为 0.167.0，PaperMod 固定到 d376885。环境初始化时校验官方 Hugo 下载包的 SHA256。

搜索与评论#

搜索在浏览器中读取本站生成的文章索引，能搜索标题和正文。试试在搜索页输入“正式构建”或“Hugo”。

评论使用 giscus，将讨论保存到 GitHub Discussions。读者需要登录 GitHub 才能发表评论，不需要独立的评论服务器。

以后绑定自己的域名#

文章路径保持为 /posts/英文-slug/。以后添加自定义域名时，更新站点地址并配置 Pages 即可；评论按文章路径关联，换域名时可以继续使用。

本次搭建的验证#

本地项目保存在 F 盘，Hugo 使用便携安装并校验官方 SHA256；主题固定到同一个提交版本。源码仓库与网页仓库分别使用私有和公开权限，Git 提交只使用网名与 noreply 邮箱。

已经检查中文标题、正文后段关键词和英文技术词的搜索。测试草稿及其配图、未来日期文章未进入正式网页、搜索或 RSS；九篇临时文章的构建也验证了每页八篇的分页。

电脑和手机视口均已检查，手机代码复制按钮保持可见。发布前先完成正式构建，再成功备份源码，最后推送网页；本地模拟还验证了更新、删除、历史恢复及失败构建保护。
